# hono-preact-ui v0.5.0: release notes (draft)

**Status:** draft; accumulates as the #260 tier-2 PRs merge. The spun-out
issues (#331, #333, #334) were written against "0.4.0", but 0.4.0 shipped on
2026-08-09 with v0.13.0; these changes land in **0.5.0**.

Three changes, one per PR: a new mid-level part set (#388), built-in Combobox
filtering (#387), and a convention cleanup (#386). Two of them are breaking on
public styling/customization contracts and one changes default behavior, hence
the minor bump.

## Versions

| Package | From | To | Why |
|---|---|---|---|
| `hono-preact-ui` | 0.4.0 | **0.5.0** | breaking data-attr and Value-part contracts; Combobox filters by default; new Listbox part set |

## New: the Listbox part set (#334, PR #388)

`Listbox.Root` / `Input` / `List` / `Option` / `Status` / `Empty`: the
mid-level parts for command palettes and custom listboxes. The APG
combobox-with-listbox pattern via `aria-activedescendant`, without Select's
value ownership or Combobox's floating machinery. You own the option set;
the parts own ids, ARIA wiring, keyboard navigation, highlight, commit, and
announcements. Docs: `/docs/components/listbox`. Purely additive.

## Behavior change: Combobox filters by default (#331, PR #387)

`Combobox.Root` gains `filter?: ((label: string, query: string) => boolean) |
null`, defaulting to the exported `matchSubstring`. Options that fail the
filter unmount; `create` options always stay visible; non-string option
children need `itemToString` to supply a label.

**What to check when you upgrade.** A combobox that previously showed all
options while you filtered them yourself now filters against the typed query
on its own:

- If you filter in your own code (server-side, in an effect, or in render),
  pass `filter={null}` to restore the old never-filters behavior, or delete
  your wiring and let the default do it.
- `autocomplete="none"` static suggestion lists want `filter={null}`.

## Breaking: presence-style Toast data attributes (#333, PR #386)

`Toast.Root`'s `data-expanded="true" | "false"` and
`data-swiping="true" | "false"` are now presence-style like every other
boolean data attribute in the package: present (empty value) when the state
holds, absent otherwise.

| Before | After |
|---|---|
| `[data-expanded='true']` | `[data-expanded]` |
| `[data-expanded='false']` | `:not([data-expanded])` |
| `[data-swiping='true']` | `[data-swiping]` |
| Tailwind `data-[expanded=true]:` | `data-expanded:` |
| Tailwind `not-data-[expanded=true]:` | `not-data-expanded:` |

## Breaking: one customization channel on the Value parts (#333, PR #386)

`Select.Value` and `Combobox.Value` no longer accept a function as
`children`. `render` is the single stateful customization channel (as on
every other part); plain children are static content.

```tsx
// before
<Combobox.Value class="chips">
  {({ selectedItems, remove }) => /* ... */}
</Combobox.Value>

// after
<Combobox.Value
  class="chips"
  render={(props, { selectedItems, remove }) => (
    <span {...props}>{/* ... */}</span>
  )}
/>
```

## Also in #386

`ContextMenu.Trigger`'s `render` now receives `{ open }` state like its
sibling triggers. Additive; no migration.
